# ซอฟต์แวร์, SaaS, อินเทอร์เน็ต, แพลตฟอร์ม

## หาเงินอย่างไร
ค่าสมาชิกรายเดือน/ปี (SaaS), ค่าไลเซนส์ + ค่าบำรุงรักษา, ค่าโฆษณา, ค่าธรรมเนียม marketplace (take rate)
จุดเด่นคือต้นทุนส่วนเพิ่มต่ำมาก → margin ขยายตามขนาดได้

## ตัวชี้วัดสำคัญ
| ตัวชี้วัด | ดีคือ | ทำไม |
|---|---|---|
| ARR / รายได้ประจำ | สัดส่วน recurring 80%+ | คาดการณ์ได้ |
| NRR (ลูกค้าเดิมจ่ายเพิ่ม) | 110%+ (enterprise ดีมาก 120%+) | ต่ำกว่า 100% = ลูกค้าเดิมใช้น้อยลง |
| Gross retention / churn | GRR 90%+ | switching cost จริง |
| Gross margin | 75%+ | ต้นทุนส่งมอบต่ำ |
| Rule of 40 (การเติบโตรายได้ % + FCF margin %) | ≥ 40 | สมดุลระหว่างโตกับทำกำไร |
| SBC ÷ รายได้ | < 10% (เกิน 20% ถือว่าสูง) | **ค่าใช้จ่ายจริง** ที่ FCF ไม่ได้หัก — แอพหักให้แล้วใน Owner Earnings |
| CAC payback | < 24 เดือน | ประสิทธิภาพการขาย |
| RPO / cRPO | โตเท่าหรือเร็วกว่ารายได้ | รายได้ในอนาคตที่เซ็นสัญญาแล้ว |
| อินเทอร์เน็ต/โฆษณา: ผู้ใช้งาน (DAU/MAU), รายได้ต่อผู้ใช้ (ARPU), engagement | | |
| Marketplace: GMV, take rate, ความถี่การซื้อซ้ำ | | |

## MOAT ที่พบบ่อย
Switching cost (ระบบหลังบ้านองค์กร, ข้อมูลอยู่ในระบบ, ทักษะพนักงาน), network effect (แพลตฟอร์ม, marketplace), ข้อมูลและ AI ที่ดีขึ้นตามจำนวนผู้ใช้, ระบบนิเวศของนักพัฒนา

## เรื่องเฉพาะยุค AI
- AI ทำลาย moat หรือเพิ่ม moat? (AI ทำซอฟต์แวร์ทั่วไปได้ถูกลง แต่ข้อมูลเฉพาะและการผูกอยู่ใน workflow ยังมีค่า)
- ต้นทุนประมวลผล AI กด gross margin ไหม
- capex ศูนย์ข้อมูลพุ่ง → Owner Earnings ในแอพลดลงชั่วคราว ต้องแยกให้ได้ว่าเป็นการลงทุนเพื่อโต (growth capex) ไม่ใช่การรักษาธุรกิจเดิม

## Red flags
NRR ลดต่อเนื่อง, การเติบโตมาจากการซื้อกิจการ, SBC สูงจนจำนวนหุ้นเพิ่มเกิน 2–3% ต่อปี, เปลี่ยนนิยามตัวชี้วัด, รายได้กระจุกในลูกค้าไม่กี่ราย, ผู้ใช้งานลดในตลาดหลัก

## ประเมินมูลค่า
DCF จาก FCF **หลังหัก SBC**, EV/Sales เทียบ Rule of 40, EV/FCF · ตัวเลข "โตที่ราคาคาดไว้" ในแอพเหมาะมากกับกลุ่มนี้

## คำถามสำหรับ earnings call
แนวโน้ม NRR และ churn, ระยะเวลาปิดดีล (sales cycle), การสร้างรายได้จาก AI, margin หลังลงทุน AI, แผนลด SBC
